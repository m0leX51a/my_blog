# Parsing

# **What is Parsing?**

Parsing is the process of analyzing a sequence of tokens (such as code or markup) to determine its grammatical structure with respect to a given formal grammar. The parser breaks down the input into smaller components (usually a parse tree or abstract syntax tree) that can be more easily processed by the system.

## **Parsing in HTML**

When a browser receives HTML content, it goes through a complex parsing process to convert the markup into a rendered webpage.

### **HTML Parsing Lifecycle:**

1. **Network Request**:
    - Browser requests HTML document from server
    - Receives response with HTML content
2. **Raw Bytes to Characters**:
    - Browser receives raw bytes
    - Converts bytes to characters based on encoding (UTF-8, etc.)
3. **Tokenization**:
    - HTML tokenizer scans characters and identifies tokens
    - Tokens include start tags (**`<div>`**), end tags (**`</div>`**), attributes, comments, text
4. **Tree Construction**:
    - Tokens are converted into DOM nodes
    - Parser maintains a stack of open elements
    - When start tag is encountered, new node is created and added as child of current node
    - End tags pop elements from the stack
5. **DOM Tree Construction**:
    - Document object model is built incrementally
    - Special cases: parsing **`<script>`**, **`<style>`**, and other elements
6. **Resource Loading**:
    - External resources (CSS, images, scripts) are discovered and loaded
    - Scripts may block parsing depending on attributes
7. **DOMContentLoaded Event**:
    - Fired when initial HTML is fully parsed
    - DOM is ready, but external resources may still be loading
8. **Load Event**:
    - Fired when all resources are loaded
    - Page is fully ready

## **Parsing in JavaScript**

### **JavaScript Parsing Lifecycle:**

1. **Loading**:
    - Script is fetched (if external) or taken from inline content
2. **Lexical Analysis**:
    - Source code is broken into tokens (keywords, identifiers, operators, etc.)
3. **Syntax Analysis**:
    - Tokens are parsed according to JavaScript grammar
    - Abstract Syntax Tree (AST) is constructed
4. **Compilation**:
    - Modern JavaScript engines use Just-In-Time (JIT) compilation
    - Code is converted to bytecode or machine code
5. **Execution**:
    - Compiled code is executed
    - Variables are allocated memory
    - Functions are called

## **Browser Parsing Pipeline**

The complete browser parsing and rendering pipeline involves coordination between HTML, CSS, and JavaScript parsing:

1. **HTML Parsing**: Build DOM tree
2. **CSS Parsing**: Build CSSOM (CSS Object Model)
3. **JavaScript Parsing/Execution**: Can modify DOM/CSSOM
4. **Render Tree Construction**: Combine DOM and CSSOM
5. **Layout (Reflow)**: Calculate positions and dimensions
6. **Paint**: Fill in pixels
7. **Composite**: Layer management for efficient updates

### **Critical Rendering Path:**

1. **Construct DOM**: Parse HTML → Tokens → Nodes → DOM
2. **Construct CSSOM**: Parse CSS → CSSOM
3. **JavaScript Compilation/Execution**: Parse/compile/execute JS
4. **Create Render Tree**: DOM + CSSOM
5. **Run Layout**: Compute geometry
6. **Paint**: Convert to pixels

## **Lifecycle Events in Browser Parsing**

1. **DOMContentLoaded**:
    - Fired when initial HTML is fully parsed and DOM is built
    - Doesn't wait for stylesheets, images, subframes
2. **load**:
    - Fired when all resources are loaded
    - Includes images, stylesheets, etc.
3. **beforeunload/unload**:
    - Fired when page is being unloaded
