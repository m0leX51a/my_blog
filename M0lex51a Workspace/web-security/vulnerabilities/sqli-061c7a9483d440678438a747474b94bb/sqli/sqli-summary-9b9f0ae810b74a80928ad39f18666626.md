# Sqli summary

1. **Identify Injection Points:**
    - Look for user input fields, such as login forms, search bars, or parameters in URLs, where data is sent to the backend database.
    - Try inserting special characters like single quotes ('), double quotes ("), semicolons (;), or SQL keywords like 'OR' and 'AND' to see if the application is vulnerable to SQL injection.
2. **Understand the Database Backend:**
    - Determine the type and version of the database (e.g., MySQL, PostgreSQL, SQL Server) as different databases have different SQL syntax.
3. **Exploit SQL Injection:**
    - Use basic payloads to understand the database structure:
        - **`' OR 1=1 --`** (commenting out the rest of the query)
        - **`' UNION SELECT 1,2,3 --`** (testing UNION operator)
        - **`' ORDER BY 1 --`** (testing ORDER BY clause)
4. **Retrieve Database Information:**
    - Exploit vulnerabilities to retrieve information about the database:
        - **`' UNION SELECT table_name, column_name, null FROM information_schema.columns --`** (to fetch table and column names)
5. **Error-Based Techniques:**
    - Inject queries that intentionally cause errors to extract information:
        - Use payloads that trigger error messages to reveal database structure or data.
6. **Blind SQL Injection:**
    - If direct retrieval of data isn't possible, exploit blind SQL injection by sending queries that return true/false responses.
        - Payloads with logical conditions like **`' OR 1=1 --`** and **`' OR 1=2 --`** to observe different application behaviors.
7. **Use Automated Tools:**
    - Tools like SQLMap, Havij, or Burp Suite's SQLi features can help automate the process and identify vulnerabilities faster.
8. **Referencing Database Functions:**
    - Utilize database-specific functions or syntax:
        - MySQL: **`SELECT version(), database(), user()`**
        - SQL Server: **`SELECT @@version, DB_NAME(), SYSTEM_USER`**
